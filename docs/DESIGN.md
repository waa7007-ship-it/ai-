# 설계안: 인플루언서 협업 제안 메일 관리 (테스트 버전)

인플루언서가 받는 협업·협찬 제안 메일을 정리해 주는 프로그램입니다.
파이썬으로 만들고, 처음에는 고객 5명으로 시작합니다.

---

## 1. 확정된 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 메일함 | **고객마다 전용 Gmail 1개씩** | 고객 정보가 처음부터 완전히 나뉨 (규칙 6) |
| 하루 요약(다이제스트) | **메일함에 "초안"으로만 저장** | 자동 발송을 하지 않으므로 규칙 4를 그대로 지킴 |
| 요약 받는 사람 | **고객 각자가 자기 요약만** | 다른 고객 정보와 섞이지 않음 (규칙 6) |
| AI | **Claude API** | 분류·추출·답장 초안 작성에 사용. 쓴 만큼 요금 발생 |
| 실행 장소 | **내 컴퓨터** | 가장 간단함. 자동 실행 시간에 컴퓨터가 켜져 있어야 함 |

### 참고 사항
- 메일 내용이 AI 회사(Anthropic)로 전달됩니다. 고객에게 미리 알리고 동의를 받습니다.
- Gmail은 권한을 "초안만"으로 좁힐 수 없습니다.
  - 초안 저장 권한에는 발송 권한이 붙어 있습니다.
  - 라벨 권한에는 휴지통 이동 권한이 붙어 있습니다.
  - 그래서 **프로그램 안에서 막습니다.** 발송·삭제 기능은 코드에 넣지 않습니다. 그런 기능을 부르면 멈추는 안전장치와, 안전장치를 확인하는 검사를 만듭니다.

## 2. 기능

1. 고객별 전용 메일함에서 새 메일 가져오기
2. 분류: 협업 제안 / 광고·스팸 / 기타
   - 광고·스팸에는 **라벨만** 붙입니다. 삭제하거나 옮기지 않습니다.
3. 협업 제안에서 브랜드명, 제안 내용, 예산, 마감일 뽑기
4. 고객 프로필(말투, 최소 단가, 거절 업종)을 반영한 답장 **초안** 작성 (발송 X)
5. 하루 한 번 고객별 요약을 그 고객 메일함에 **초안**으로 저장 (발송 X)

## 3. 폴더 구조

```
ai-/
├── CLAUDE.md               ← 작업 규칙
├── README.md               ← 사용 설명서
├── .gitignore              ← GitHub에 올리지 않을 파일 목록
├── .env.example            ← 필요한 비밀 정보의 "이름"만 적은 견본
├── requirements.txt        ← 설치할 부품(라이브러리) 목록
├── docs/
│   └── DESIGN.md           ← 이 설계안
│
├── src/                    ← 프로그램 본체
│   ├── main.py             ← 시작 버튼 역할 (전체 순서대로 실행)
│   ├── fetch_mail.py       ← (1) 새 메일 가져오기
│   ├── classify.py         ← (2) 분류
│   ├── extract.py          ← (3) 정보 뽑기
│   ├── draft_reply.py      ← (4) 답장 초안 만들기
│   ├── digest.py           ← (5) 하루 요약 만들기
│   ├── safety.py           ← 안전장치 (수상한 문구 감지, 발송·삭제 차단)
│   └── client_store.py     ← 고객 폴더 관리 (다른 고객 폴더 접근 차단)
│
├── tests/                  ← 검사용
│   └── sample_emails/      ← 연습용 가짜 메일 (진짜 고객 정보 없음)
│
└── data/                   ← 고객 데이터 (GitHub에 안 올라감)
    └── clients/
        ├── client_01/
        │   ├── profile.yaml    ← 이름, 말투, 최소 단가, 거절 업종
        │   ├── token.json      ← 이 고객 Gmail 로그인 정보
        │   ├── mails/          ← 가져온 메일
        │   ├── results/        ← 분류·추출 결과
        │   ├── drafts/         ← 만든 답장 초안 (사본)
        │   └── digests/        ← 하루 요약 (사본)
        ├── client_02/
        └── ... (5명)
```

- 폴더 이름은 한글 대신 `client_01`처럼 짓습니다. 한글 이름은 컴퓨터에 따라 오류가 날 수 있습니다.
- 고객 실제 이름은 `profile.yaml` 안에 적습니다.

## 4. 단계별 계획

진짜 메일함은 **5단계에서야** 연결합니다. 그 전에는 가짜 메일로 연습합니다.

| 단계 | 할 일 | 확인 방법 |
|---|---|---|
| 0 | 파이썬 설치, 작업 공간 준비 | "준비 완료" 글자가 화면에 나오는지 |
| 1 | 고객 폴더 5개와 프로필 파일 만들기, 읽어 오기 | 고객 5명의 이름·최소 단가가 목록으로 나오는지 |
| 2 | Claude API 연결 + 가짜 메일 분류 + 안전장치 | 가짜 메일이 맞게 나뉘는지, "이전 지시를 무시해"가 든 메일이 "수상함"으로 표시되는지 |
| 3 | 협업 메일에서 정보 뽑기 | 브랜드명·예산·마감일이 표로 나오는지 |
| 4 | 프로필을 반영한 답장 초안 (파일로만 저장) | 거절 업종에는 거절, 단가가 낮으면 조정 요청 초안이 나오는지 |
| 5 | 진짜 Gmail 연결, 읽기만 | 최근 메일 제목이 화면에 나오는지 |
| 6 | Gmail에 라벨 붙이기 + 답장 초안 저장 | Gmail에서 라벨과 임시보관함 초안이 보이는지 |
| 7 | 하루 요약을 고객 메일함에 초안으로 저장 | 임시보관함에 요약 초안이 보이는지 |
| 8 | 내 컴퓨터에서 하루 한 번 자동 실행 설정 | 다음 날 정해진 시간에 결과가 생기는지 |
| 9 | 고객 5명 전체 적용 및 최종 점검 | 고객별 폴더에 각자 결과만 있는지 |

## 5. 용어 설명

| 용어 | 쉬운 설명 | 처음 나오는 단계 |
|---|---|---|
| 파이썬 | 프로그램을 만드는 언어. 문법이 쉬운 편 | 0 |
| 터미널 | 글자로 컴퓨터에 명령하는 창. 명령어를 붙여 넣는 곳 | 0 |
| 가상환경 | 이 프로젝트 전용 부품 상자. 다른 프로그램과 섞이지 않게 함 | 0 |
| 라이브러리 | 남이 미리 만들어 둔 부품 (예: Gmail 연결 부품) | 0 |
| YAML 파일 | 메모장으로 고칠 수 있는 설정 파일. `최소단가: 500000` 형식 | 1 |
| API | 다른 서비스(AI, Gmail)에 일을 시키는 정해진 창구 | 2 |
| API 키 | 그 창구를 쓰기 위한 비밀번호. `.env`에만 저장 | 2 |
| 프롬프트 | AI에게 주는 작업 지시문 | 2 |
| 프롬프트 인젝션 | 메일 속에 AI를 속이는 문장을 숨기는 공격 | 2 |
| 추출 | 긴 글에서 필요한 정보만 뽑아내는 것 | 3 |
| JSON | 뽑은 정보를 `{"브랜드": "OO"}`처럼 정리해 담는 형식 | 3 |
| 초안(Draft) | 다 써 두었지만 보내지 않은 메일 | 4 |
| Gmail API | 프로그램이 Gmail을 다루게 해 주는 구글의 창구 | 5 |
| OAuth | 구글 화면에서 "이 프로그램이 내 메일을 봐도 됨"을 허락하는 과정 | 5 |
| 권한 범위(스코프) | 허락해 주는 일의 범위 (예: 읽기만, 초안 만들기) | 5 |
| 라벨 | Gmail 메일에 붙이는 이름표. 메일을 옮기지 않음 | 6 |
| 다이제스트 | 하루 동안 온 메일을 모은 요약 | 7 |
| 스케줄러 | 정해진 시간에 프로그램을 자동 실행해 주는 기능 | 8 |
